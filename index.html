中秋与国庆

亲爱的朋友

朋友，这封信来晚了，本来应该中秋就写的，没想到国庆也已经过了 3 天了，才终于提笔写起来。祝你中秋，国庆快乐！

想念爷爷奶奶

每到中秋，都非常想念爷爷奶奶。我永远记得，在老家住的 3 个月，是我一生中最快乐的日子。

爷爷写得一手好字，奶奶能烧一手好菜；爷爷说话慢条斯理，奶奶说话噼里啪啦；爷爷常坐在大厅的一角，看着门外，奶奶总进进出出，屁股总没有坐下的时候。

我记得，正是贪玩的年纪，小朋友喊我出去玩，我放下笔就跑出去了，回来看到爷爷跟我说，你看你一急就把题目写错了。下一次小朋友喊我时，我再心急也把题目做完了，但是此时小朋友早就一溜烟跑没影了。

我记得，奶奶喜欢背着我，到村广场的早餐店里吃肠粉，那时候趴在奶奶的背上，感受到奶奶温暖粗糙的手，时不时提一提，拉一拉我。

我记得和不记得都都还有很多，但每大一岁，就会愈发想念爷爷奶奶，想念那个无忧无虑的午后。

看《欢迎来龙餐馆》

我和老妈一起去看了《欢迎来龙餐馆》是由沈腾、蒋明奇主演，文牧野导演的一部反战剧情片。我是冲着网络上的评价才去看的，看完之后，我认为它的好看程度甚至超越了网络的评价。我最大的感受是，这部电影其剧情之精彩，对战争的反思之深刻，堪比尼古拉斯·凯奇主演的名作《战争之王》——甚至是超越。在这部影片里，沈腾扮演的徐福作为被当地冲突波及到的外乡人，提供了一个第三方视角来看待这场冲突。走私酒水这件事，刚好将所有角色都收集了起来，走私酒水的通行证，本地人扎伊德提供了帮助，但它服务的对象却是一帮侵略了这个国家的外国人。

最关键的是，这部片子描绘的战争十分平等，它平等地对待了在影片里出现的每一个角色所代表的一群人，包括徐福自己：被占领国的民众死了，侵略者的士兵死了，恐怖分子也死了，徐福身边的朋友也死了。

《欢迎来龙餐馆》有三条故事线，我一直在品味：

  • 扎伊德是徐福的老板，后来变成合作伙伴，在妻子、女儿全被杀害之后，彻底地变成了恐怖主义分子，为了杀掉美国人，他愿意付出任何代价；
  • 托尼·王所扮演的美军大兵，每一次喝醉酒都哭着喊回家，但最终被恐怖主义的袭击炸死，他一直做着安防工作，并没有主动袭击当地平民；
  • 赛夫自小父母双亡，心怀仇恨，后来被徐福他们收养，成为了徒弟，与徐福情同父子。尽管他深受徐福他们的感染，行事上不再那么偏激，但内心仇恨没有淡化，看到徐福被伤害的时候，他还是忍不住想拔刀杀人。这一部分仇恨非常写实，因为身负如此深仇大恨，塞夫这种表现才是合理的。即便到了恐怖分子的基地，塞夫也一心想成为一名的战士，直到他看到阿里这一帮恐怖分子只是以圣战为名行欺骗之实，将他们这帮孩子，当成了运送人肉沙包的工具。他才真正明白了那种「荒谬」。

我觉得《欢迎龙餐馆》很好看，它的写实主义没有参杂太多「戏谑感」，而是像纪录片一样，准确真实地反映了一个中国厨子远在他乡的遭遇。而在这个故事中，作为观众的我们，没有感受到价值观被调教，而是跟随着故事，自然而然地产生了感受。

我非常赞赏文牧野的创作方法，我查了一下，他 1985 年出生，也可以被称为「最强 80 后」之一了。

去马庵还愿

马庵位于南屏，当今被称为南屏观音庙，相传是葛洪（又称抱朴子）在罗浮山隐居时，受邀到此地游历讲道，遂建成马庵。

马庵里有一濂泉洞，常年流有泉水，是附近人家一直以来重要的水源地。

为了本次还愿，老爸提前了差不多一个星期准备。先是找到一个地方订供神用的母鸡、烧猪肉、苹果，然后准备好纸宝、香、烧酒等物。说来很巧，上个星期，老妈买了一些苹果，刚好剩下 6 个用于还愿，不用另外准备。菩萨有灵！

当前上午 7 点多时，我们全家出发，取了母鸡和烧肉，直奔马庵。从山脚到马庵，是一段缓缓的斜坡，刚好走到庵的入口处，下了一点雨，我们在入口的迎客亭歇了一小会，等雨停了，再走进马庵。

马庵不大，走到门口就有一道石板路引人向上，直接到濂泉洞口，也就到了观音庙。我们摆好供神用品，一家人都虔诚地拜了拜，烧了纸宝就下山了，此时，凉风阵阵，空气清新，心情一阵舒畅。

本次准备的母鸡、烧猪肉，皆购自湛祺烧腊店，位于三小附近。

要警惕赠送额度的陷阱

每一次大模型厂送额度，都让人肾上腺素激增，但用完这些赠送的额度之后，回头一看发现自己都制造了一些什么垃圾，一地狼藉，还得多另外花更多的时间来重构，理顺项目结构，清理多余的代码。

我认为，「送额度」和商场发给你的折扣券没有差别，都是一种刺激你消费欲的临时措施。至于刺激消费欲的后果，大家也知道，家里会囤积一大堆没用的东西，不舍得丢，整理又麻烦，还占了空间。

折扣券的意义和目的，就是为了消费膨胀，但不真正引导人拥有更好的生活。它只是用一种稍微轻微 的代价，为他人制造了一种「低质量」的生活幸福感——虚幻的拥有。

「送额度」也制造了「膨胀」，和「消费膨胀」一样，「代码膨胀」也是低质量的，它制造了一种「我很能干，我干了很多的」的能力幻觉。

所以我觉得「送额度」很多时候是一个陷阱。如果只是为了花光这些额度，而匆匆忙忙制定某些开发计划，我觉得后果必然是花更多的精力，去收拾烂摊子。但有一种情况，我觉得是可以享受「送额度」的，就是原本已经有一些计划，只不过暂时尚未安排，在这种情况下，使用赠送的额度来加速整个计划的执行——这完全没问题，一切都在计划之中，而且你没有花额外的精力和时间。

下一次，如果再遇到「送额度」，我觉得还是，不妨冷静下来，先看看自己原来的计划有什么可以加速，查漏补缺的地方，如果有，那么好好享受这些额度，但未来的计划提前；如果没有，那还不如按照原来的节奏走。

总之，不要因为「送额度」这件事多占用自己的时间和精力，有多余的精力可以锻炼、社交、娱乐，又或者，好好想想下一个计划。

把时间投入到高质量的方面去。

刘欢去世

看到一篇刘欢讲课的结语：

音乐真的没有什么作用，我们这个世界就是这样，我们看到西方音乐走来的这个历程了，我们看到了这么多美好的音乐，这么多优秀的音乐家不断的努力，但是怎么了，音乐没有消除过贫困，没有阻挡过战争，那些缔造出那么美好音乐的民族，他们照样去屠杀，他们照样劣迹斑斑，音乐没有什么作用。

但是对于我们来说，音乐可能又有作用。

有作用就是在我们心底，因为我们爱它，我们可以留住一个随时可以去盼望美好的希望，一个希冀而已。

实际上，音乐和所有的艺术在人类文明中的位置是一样的，就是一个不停地对美好的追问和探索。这就是有生命力的文明为什么可以一而再再而三延续生命力的原因，因为人们心底需要这种美好。而且我们看到的这个世界，我也不敢说他比以前更美好了，还是更不好了，但是我们只有一点可以告诉我们自己。如果我们更喜欢音乐，可以让我们自己更幸福、更快活。这就是我们在一起了解音乐所能达到的一点点，一点点的目的。所以，我能告诉大家的话就是，希望大家以后，爱音乐，他能给你们很多快乐。

Scott Jenson 谈计算机桌面发展

Scott Jenson 曾就职于牛蛙设计公司、苹果、诺基亚、Google，在用户体验设计上，有着超过 35 年的经验和积累，他参与过苹果最早期的操作系统的界面设计，领导过 Google 用户体验设计以及物联网方面的设计。

在 KDE 峰会上，他发表《我们真的要永远使用相同的桌面用户体验吗？》主题演讲，本次演讲：前 20 分钟是针对主流桌面操作系统的吐槽，主要是集中在苹果和微软上，紧接着 10 分钟讨论设计思想，在最后 10 分钟，针对当下桌面系统，在设计和用户体验方面的困境，他公开了自己在这方面的探索和想法。

一个问题：计算机桌面和什么有关？是那些图标，窗口，还有鼠标吗？并不是。当前的桌面设计倾向于「无状态」设计，这种方式可以让人直接操作各类数据，很强大，但它无法保存之前的状态，这也意味着如果隔了一段时间回来，之前所做的操作记忆全部消失，需要重复再操作一次。为了可以更好地解决这个问题，Scott Jenson 切换了视角，不再把桌面认为一种数据操作的模拟，而是关于「工作记忆」——该怎么管理自己的数据，才能在所有这些工具里都能查到之前的相关内容。

「我们要怎么优化工作记忆，来改进桌面用户体验？」

Scott Jenson 随后演示了他构思的三个原型：

  1. 针对宽屏所设计的窗口管理器。这个设计有意思的是，它把中间设置为工作区，两边眼睛难以覆盖到的地方，则用来拜访暂时用不到的窗口，而且随着窗口距离主窗口区越远，这些闲置窗口就会越小。
  2. 针对文件所设计的「相关侧边栏」。这个侧边栏十分万能，可以记录我们在阅读文档时的摘要，也可以存放与该文档相关的文件，甚至网页内容等等，总之可以记录和该文件相关的一切。
  3. 针对用户行为的痕迹追踪系统。他认为可以设计出一套捕获用户「注意力信号」的后台系统，以捕获用户操作的意图和行为，他希望可以通过数学计算的方式来捕获这些信号，记录用户所有的操作，然后转换成一个类似时间轴的东西。

Scott Jenson 在本次演讲里，大量援引 Alan Kay 的话，还提及了如下几个项目和论文：

  • WinFS
  • Nepomuk
  • Lifestreams: a storage model for personal data

Multi-Agent 的任务编排是否走了弯路？

「Multi-Agent 开发是一个谎言」里我提到，Multi-Agent 的开发效率未必就高，在使用 Herdr 的时候 Leader Agent 会不定时发布命令查看 Worker Agent 的工作进展，白白浪费许多 token。

与群友相互分享了很多工具，和 Vibe Coding 的经验。一开始我们讨论的是 Multica，一个看板式 Agent 调度器。但我很快就放弃了用它来指挥 Agent 开发项目——即便设计了 Leader、Reviewer、Researcher、Worker 这些角色，让它们相互之间检查，但还是很容易一个 Agent 跑偏之后，带着其它 Agent 跑偏。我之前一直是手动搬运对话方式，完全不会出现这种问题。

后来群友发现问题之所在，Multica 居然是让所有 Agent 共享一条 Session 也难怪容易集体跑偏了。

我认为 Multi-Agent 协作时，每一个 Agent 最好还是保留自己的 Session 和记忆，这样子才好纠偏。我将 SPEC-AGENTS 项目归档时，所产生的认知就是，模型能力越强，越要位它准备纯净的上下文空间，Multica 让所有 Agent 共享一条 Session，令所有 Agent 的上下文杂讯太多了，也难怪容易跑偏。

Multica 还有另外一个问题，就是尽管它提供了供人查看日志的地方，但它毕竟还是隐藏起来了。这对于我这种希望发现 AI 的错误，能够马上干预和调整的习惯不符，而且 Multica 想要调整某个正在实施任务的 Agent 的行为特别困难，基本没有对应的入口。

我发现了两个不错的编排器，希望它们能够解决一点点这里提到的问题：

https://github.com/ordewell/ordewell

https://github.com/dagu-org/dagu

我让 Agent 帮我做了一个对比：https://gist.github.com/yibie/9bf286b60285fbc9836518f69fecb496

两者的风格差异很大。
